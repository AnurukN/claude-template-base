# Scaffold-and-confirm execution model for AWS-touching skills

SageMaker skills (`/train-model`, `/deploy-model`, `/build-pipeline`) could either call the SageMaker SDK directly to submit jobs/endpoints, or generate the code/config and let the user run it. We chose the latter: skills generate code, and for `/train-model`/`/deploy-model` specifically print the exact command plus an estimated instance cost, then wait for explicit confirmation before submitting anything to AWS. This is because every SageMaker training job or endpoint deploy costs real money and is hard to undo once running, and a template meant to be copied across projects shouldn't risk silently launching billable jobs on behalf of a new user who hasn't reviewed the generated config. `/eda` is exempt since it only runs locally in the notebook.
