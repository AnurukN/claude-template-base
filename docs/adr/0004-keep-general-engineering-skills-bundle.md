# Keep the general engineering skills bundle alongside the ML-specific skills

`.claude/skills/` holds two layers: the ML-specific skills this template exists to provide (`eda`, `feature-engineering`, `train-model`, `evaluate-model`, `deploy-model`, `build-pipeline`), and a general-purpose software engineering skill bundle (`tdd`, `code-review`, `diagnosing-bugs`, `triage`, `domain-modeling`, `codebase-design`, `writing-for-agents`, `wizard`, `prototype`, `research`, and others) installed via `setup-matt-pocock-skills`. We chose to keep the general bundle rather than strip it out to keep the template ML-only, because DS/MLE work is still ordinary software engineering most of the time — writing pipeline scripts, reviewing PRs, debugging failing tests, resolving merge conflicts — and these general skills already cover that well. The Phase 1 persona-scope decision in `0002-phase-1-persona-scope.md` was about which personas get *ML-specific* skills built for them (DS/MLE, not Data Analyst); it says nothing about excluding general engineering hygiene tooling, so keeping this bundle doesn't cut against that scope. Anyone copying this template into a new repo should still run `/setup-matt-pocock-skills` once, separately from any ML-specific setup, to configure the general bundle's issue tracker and triage-label conventions for that repo.
